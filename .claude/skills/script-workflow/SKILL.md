# Script Workflow (빌드/테스트 스크립트화 규칙)

빌드·테스트·실행·실험은 **반복 가능해야 한다.** 일회성 명령을 터미널에 직접 치지 않고, 항상 `scripts/` 폴더의 스크립트를 통해 실행한다.

## 절차

1. **먼저 찾기:** 작업 전에 `scripts/` 폴더를 확인한다. 이번 작업과 관련된 스크립트가 있으면 **그 스크립트를 그대로 사용한다.**
2. **없으면 만들기:** 맞는 스크립트가 없으면 새로 작성해 `scripts/`에 저장한 다음, 그 스크립트로 실행한다.
3. **고쳐야 하면 고치기:** 기존 스크립트가 거의 맞지만 부족하면, 비슷한 스크립트를 새로 만들지 말고 기존 것을 수정한다. 단, 수정 때문에 스크립트의 목적이 흐려지면 분리한다(아래 "작게 유지").
4. **기록:** 스크립트를 새로 만들거나 의미 있게 바꾸면 `obsidian-docs` 규칙에 따라 docs에 남긴다.

## 작게 유지 (중요)

- **스크립트 하나 = 목적 하나.** 인자 플래그로 동작을 분기하는 만능 스크립트를 만들지 않는다.
  - 나쁜 예: `run.ps1 -Mode build|test|launch|clean -Target app|ext -Headless -Seed 42 ...`
  - 좋은 예: `build_app.ps1`, `launch_app.ps1`, `test_inspector.ps1`, `run_experiment.ps1`
- 인자는 **0~3개 정도**로 제한하고, 모두 합리적인 기본값을 둔다.
- 공통 로직(경로 설정, 로그 폴더 생성 등)이 반복되면 `scripts/_common.ps1` 같은 헬퍼로 빼고 각 스크립트에서 dot-source 한다.

## 작성 규칙

- **형식:** Windows PowerShell 5.1 호환 `.ps1`을 기본으로 한다. Python 로직이 필요하면 `.py`를 만들고 `.ps1`이 호출한다.
- **이름:** `동사_대상.ps1` (snake_case). 예: `build_app.ps1`, `test_tracker.ps1`, `analyze_results.ps1`.
- **헤더 주석 필수:** 맨 위에 목적, 사용법, 인자, 출력물 위치를 적는다.

  ```powershell
  <#
  목적: VisionInspector 단위 테스트 실행 (Kit 불필요)
  사용법: .\scripts\test_inspector.ps1 [-Verbose]
  출력: logs/test_inspector_<timestamp>.log
  #>
  ```
- **경로:** 스크립트 위치 기준(`$PSScriptRoot`)으로 프로젝트 루트를 계산한다. 어디서 실행해도 동작해야 한다.
- **실패 처리:** `$ErrorActionPreference = 'Stop'`을 사용하고, 외부 명령의 `$LASTEXITCODE`를 검사해 실패하면 0이 아닌 코드로 끝낸다.
- **로그:** 빌드/테스트 출력은 `logs/`에 타임스탬프 파일로도 저장한다(`logs/`는 git 제외).
- **비밀값 금지:** 계정, 토큰, 개인 경로를 하드코딩하지 않는다. 필요하면 환경 변수나 설정 파일을 쓴다.

## 실행 보고

- 실행할 때 어떤 스크립트를 썼는지 사용자에게 알린다.
- 결과는 실제 출력 그대로 보고한다. 실행하지 않은 스크립트를 "통과"라고 쓰지 않는다.
