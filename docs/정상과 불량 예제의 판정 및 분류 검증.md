# 정상과 불량 예제의 판정 및 분류 검증

정상 예제는 정상 형상을 보여주는 것뿐 아니라 실제 검사 결과 good과 실제 분류 경로 pass가 모두 확인되어야 한다. 불량 예제는 defect 판정과 reject 경로를 확인한다. 판정기 입력과 분류 로직은 변경하지 않는다.

기존 시드와 불량률 0.3을 사용하면 seed 42의 첫 제품은 정상, seed 3의 첫 제품은 미완성 가공 형상 불량이다. 녹화 스크립트는 생성된 제품의 ground_truth가 요청한 종류와 일치하는지 확인하고, 녹화 후 prediction과 분류 결정도 검사한다. ground_truth는 예제 검증에만 사용하며 판정이나 분류를 강제하지 않는다.

분류 결정 전에는 관측된 prediction으로 클립 이름을 고른다. 실제 결정이 생기면 그 경로를 우선해 정상 통과는 05_pass, 불량 배출은 05_reject로 저장한다. SORTED 상태의 정상 제품은 배출선을 지나 계속 벨트를 이동하며, 그 모습을 1.2초 더 녹화한다.

[[부품 추적 확대 렌더링]]과 [[다중 뷰포트 캡처와 화면 합성]]의 같은 카메라와 해상도를 사용한다. 정상 예제는 한 제품만 투입하고 검사·확대 뷰포트를 순차 재사용해 GPU 메모리 부담을 줄인다. 카메라 전환 시 시뮬레이션을 멈추고 12개 렌더 프레임을 기다린 뒤 이어서 녹화하므로 출력의 시뮬레이션 시간과 프레임 설정은 유지된다. 정상 제품은 SORTED 이후에도 벨트 위에 남아 있어 다음 제품 없이 통과 장면을 기록할 수 있다.

결과 metadata에는 ground_truth, prediction, route와 run_id를 보존한다. 적용 작업은 [[2026-11-03 README 정상 제품 예제 추가]]에 기록한다.
