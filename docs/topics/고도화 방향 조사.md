# 고도화 방향 조사 (2026-10-23)

사용자 요청: 포트폴리오용으로 시뮬레이션을 더 고도화하고 싶다. Omniverse 안에서 비전 검사 모델을 올려 테스트할 수 있는가? Seeed reBot Arm을 불러와 쓸 수 있는가?

## 확인한 사실 (이 PC에서 실측)
| 질문 | 답 | 근거 |
|---|---|---|
| Omniverse 안에서 비전 모델 추론? | **가능.** Kit Python에 ONNX Runtime을 설치해 검사 콜백 안에서 GPU(DirectML)/CPU로 추론 | [[Kit 110.4 레지스트리와 Kit 안 ONNX 추론 실측]] |
| 학습 데이터를 Omniverse에서? | **가능.** `omni.replicator.core` 1.13.38이 이 Kit 레지스트리에 있다(도메인 랜덤화, annotator) | 같은 노트 |
| Seeed reBot Arm? | **가능.** 공식 URDF + STL을 USD로 바꿔 FK로 관절 구동 렌더까지 확인 | [[Seeed reBot Arm URDF를 USD로 가져오기]] |
| Isaac Sim(URDF importer, ROS 2 bridge)? | 이 PC는 공식 최소 사양(RTX 4080 16 GB) 미달. 이 레지스트리에도 없다 | 같은 노트 |
| PhysX? | `omni.physx` 110.4.4 사용 가능 | 같은 노트 |

## 제안 (포트폴리오 효과 순)

### A. 합성 데이터 → 모델 학습 → 디지털 트윈 안에서 검증 (비전 AI 파이프라인)
1. **Replicator로 데이터 생성:** 검사 셀의 다섯 시점마다 조명, 셰이드(재질), 카메라 미세 흔들림, 제품 자세를 무작위로 바꾸고, 시점별 이미지와 라벨을 수천 장 만든다. 정답은 생성기가 알고 있으니 라벨 비용이 없다.
2. **Kit 밖에서 학습(PyTorch, RTX 4060):** 두 가지를 비교한다.
   - (a) 소형 분류기(시점별, good/defect)
   - (b) 이상 탐지(정상품만으로 학습: PaDiM/PatchCore 계열). 실제 공장처럼 불량 표본이 적은 상황에 맞는다.
3. **ONNX로 내보내 Kit 안에서 추론:** 규칙 검사기와 같은 프레임으로 나란히 판정하고 같은 지표로 비교한다.
   - 비교 조건: 조명 default/dark, 미지의 결함 종류(학습에 없던 결함)
   - 지금의 가장 큰 약점(어두운 조명에서 FP 29/29)을 데이터로 개선했는지가 핵심 이야기가 된다.
- 주의: 평가 데이터는 학습에 쓰지 않는다(seed 분리). 합성 데이터로만 학습했으니 sim-to-real 한계는 그대로 남는다(Cosmos Transfer 같은 사진화는 이 PC의 GPU로는 어렵고 참고만 한다).

### B. reBot Arm으로 벨트↔검사 셀 이송 (로봇 통합)
- 지금은 제품이 포물선 호로 순간 이동하듯 옮겨진다. 이를 **reBot Arm 픽앤플레이스**로 바꾼다.
  - 순서: 1구간 끝에서 집기 → 플래터에 놓기, 플래터에서 집기 → 2구간에 놓기
  - 셀이 처리하는 동안 팔은 다음 제품을 대기 위치로 미리 옮긴다(파이프라이닝)
- **IK**(감쇠 최소제곱, numpy, `core/`에서 테스트), 관절 속도 제한과 경로 보간, 그리퍼 개폐. 사이클 시간에 팔 이동이 들어가 라인 용량 실험이 더 현실적이 된다.
- 확장(하드웨어가 있을 때): Seeed Python SDK(USB-CAN)로 **실제 팔과 연동**한다. 시뮬레이션 관절값을 실제 팔에 보내거나, 실제 관절값을 트윈에 반영한다. 이 PC에는 하드웨어가 없어 확인하지 않았다.

### C. 물리(PhysX)
- 배출 bin으로 떨어지는 제품, 벨트 위 마찰 반송을 강체로 바꾼다. 파지(그리퍼 접촉)는 물리로 하기 어렵다. 집는 동안은 키네마틱으로 붙이고(attach), 놓은 뒤 물리로 넘기는 혼합 방식이 현실적이다.
- 포트폴리오 효과는 중간이고, 결정론(같은 seed = 같은 결과)이 깨지지 않게 하는 비용이 크다.

### D. 운영 지표와 공개
- OEE(가용성 × 성능 × 품질), 시나리오 실행기, WebRTC 스트리밍(`omni.kit.livestream.webrtc`)으로 브라우저 데모
- 데모 영상과 GitHub 공개(남은 Day 10 항목)

### E. 표면별 티칭 재현 (사용자 요청, 2026-10-24) — 완료: [[2026-10-24 Day13 표면별 티칭]]
사용자는 실제 치아 가공기에서 크라운의 각 표면에 대해 티칭을 해 본 경험이 있다. 이를 Omniverse에서도 해 보고 싶어 한다.
- 지금 검사 셀의 시점 5개는 역기구학으로 자동 계산한 자세다. 이를 **티칭 포인트 기반**으로 바꾼다.
  - 실제 티칭 데이터를 불러와 재생한다(X/Y/Z/B/C 축값, 또는 G-code나 컨트롤러 내보내기)
  - 관절 한계와 카메라 시야를 검증한다
- Kit 안의 **티칭 UI**: 축 조그(jog) 슬라이더와 스핀들 카메라 실시간 화면을 보면서 표면마다 포인트를 저장한다 → 시점 목록(catalog)으로 쓴다
- 비교: 티칭한 시점과 자동 시점의 검출률과 사이클 시간
- 시작하기 전에 확인할 것: 티칭한 대상(검사 시점인지 가공 경로인지), 데이터 형식, 기계가 `teeth_mill.urdf`와 같은 구조인지

## 마무리 (2026-10-24, 사용자 결정)

1. **B. reBot Arm 이송.** 사용자가 회사에서 다뤄 본 실제 장비이고, 화면에서 바로 보이는 효과가 크다. PoC가 이미 됐다.
2. **A. 합성 데이터 → 모델 → 트윈 안 검증.** "Omniverse로 비전 AI를 만들고 검증한다"는 포트폴리오의 핵심 이야기다. 조명 약점을 실측으로 개선했는지 보여 줄 수 있다.
3. C와 D는 남는 시간에 한다.
