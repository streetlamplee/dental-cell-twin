# 스크립트 목록

`scripts/`의 모든 스크립트는 프로젝트 루트 어디서 실행해도 된다. 실행 로그는 `logs/`(git 제외)에 남는다.

## 터미널별 실행 방법
| 터미널 | 명령 |
|---|---|
| PowerShell | `.\scripts\launch_app.ps1` |
| Git Bash / cmd | `powershell -NoProfile -ExecutionPolicy Bypass -File scripts/launch_app.ps1` |

- Git Bash에서 `.\scripts\...`라고 치면 `\`가 사라져 `command not found`가 난다. 또 bash는 `.ps1`을 직접 실행하지 못한다.
- PowerShell에서 "이 시스템에서 스크립트를 실행할 수 없으므로…"(`PSSecurityException`)가 나면, 실행 정책이 기본값 `Restricted`이기 때문이다. 둘 중 하나를 쓴다.
  - 매번 우회: `powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\<script>.ps1`
  - 한 번만 설정(관리자 권한 불필요): `Set-ExecutionPolicy -Scope CurrentUser -ExecutionPolicy RemoteSigned`

| 스크립트 | 목적 | 언제 |
|---|---|---|
| `setup_kit_template.ps1 [-Branch 110.4.0]` | kit-app-template을 루트에 받기 | 최초 1회 |
| `list_templates.ps1` | 템플릿 목록 (대화형 UI라 Agent 셸에서는 실패) | 참고용 |
| `new_from_template.ps1 -PlaybackFile <toml>` | replay 파일로 앱/확장 생성 | 앱/확장 추가 시 |
| `build_app.ps1` | `repo.bat build` | 최초, 앱/확장 추가 시 |
| `launch_app.ps1` | VisionTwin GUI 실행 | 수동 확인, 시연 |
| `render_smoke.ps1 [-Frames 240] [-Part box] [-Lighting default] [-ViewScale 0.5]` | GUI 앱 자동 실행 → 씬 생성 → Viewport PNG 저장 → 종료 (`render_smoke.py` 사용) | 씬/조명/카메라 수정 후 |
| `probe_capture.ps1` | Gate B 진단: 검사 카메라 버퍼 캡처 성공 여부 (`probe_capture.py`) | 캡처/렌더 관련 수정 후 |
| `collect_frames.ps1 [-Seed 42] [-Products 30] [-Speed 0.5]` | 1회 전체 run: 프레임, 실시간 판정, 배출 → inspections.csv, results.csv, summary.json (`collect_frames.py`) | 데이터 수집, 실험 |
| `compare_runs.ps1 -RunA <a> -RunB <b>` | 두 run의 results.csv 결정론적 컬럼 비교(재현성) | 같은 시드 재실행 후 |
| `setup_cad_env.ps1` | CAD용 venv(.venv-cad: cadquery, usd-core) | 최초 1회 |
| `urdf_to_step.ps1 [-Urdf]` | URDF → STEP 어셈블리(mm, 색, 박스 필렛·원통 챔퍼; URDF bbox 유지) + kinematics.json | URDF 변경 시 |
| `probe_cad_converter.ps1 -Stp <f>` | Gate C 진단: USD converter로 STP 1개 변환, 구조 출력 | 변환기 문제 조사 |
| `convert_step_to_usd.ps1 -Stp <f> [-Out] [-Profile product] [-TessLOD n]` | USD converter(HOOPS)로 STEP → USD. 옵션은 `config/cad_converter_options.json`의 프로파일(legacy/machine/product). `<usd>.convert.json`에 변환 기록 | STP 하나만 변환할 때 |
| `convert_all_cad.ps1 [-Name]` | `config/cad_assets.json`의 자산 전체를 자산별 프로파일과 LOD로 다시 변환 + 품질 리포트 + 밀링기 URDF 검증 | STP나 변환 옵션을 바꾼 뒤 |
| `report_cad_usd.ps1 -Usd <u> -Step <s>` | 변환 품질 리포트: 메시/삼각형/재질/메타데이터, STEP B-rep 대비 부피·면적·크기 오차 → `<usd>.report.json` (.venv-cad) | 변환 후 |
| `compare_tess_lod.ps1 -Stp <f>` | LOD 0~4로 각각 변환해 삼각형 수와 정확도를 비교 → `results/cad_lod/<이름>/table.md`, `lod_compare.png` (`summarize_tess_lod.py`) | 자산 LOD를 정할 때 |
| `verify_cad_usd.ps1 [-Name]` | 변환 USD를 URDF와 비교(이름, 위치, bbox, 색) | 변환 후 매번 |
| `fetch_parts.ps1 [-Name]` | `assets/parts/sources.json`의 부품 STEP 다운로드 + SHA256 확인 | 최초, 부품 추가 시 |
| `inspect_step.ps1 -Path <glob>` | STEP 어셈블리 구조, 솔리드 수, 색, 크기 출력 | 부품 후보 평가 |
| `make_part_variants.ps1 [-Part kfl08]` | 부품 제품 변형 USD 레이어 생성(가공 부품은 raw/final 두 단계) | 카탈로그 변경 시 |
| `make_dental_parts.ps1` | 치과 제품 모델(블랭크, 크라운, 미완성 크라운) STEP 생성(CadQuery) | 모델 변경 시 |
| `check_run.ps1 [-RunDir]` | run 감사: events.csv 일관성 + summary 카운터 | 모든 run 뒤 |
| `bench_render.ps1 [-Scale] [-Products]` | 메인 Viewport 렌더 배율별 벽시계 시간 | 성능 조정 |
| `run_experiments.ps1 -Config <json>` | 실험 조건 행렬을 차례로 run(끝난 조건은 건너뜀) → `results/experiments/<name>/runs` | 실험 |
| `analyze_results.ps1 -Experiment <name>` | 실험 run 집계 → table.csv/md, fig_vision.png, fig_views.png(윗면만 vs 다섯 시점), fig_line.png (`analyze_results.py`) | 실험 후 |
| `probe_extensions.ps1 -Names <a,b>` | 이 Kit 레지스트리에 확장이 있는지(최신 호환 버전), 아무것도 켜지 않음 (`probe_extensions.py`) | 새 기능 조사 |
| `probe_onnx_in_kit.ps1` | Kit 안 ONNX Runtime 추론 확인(DirectML/CPU, 소형 CNN, 640×480) | 모델 추론 조사 |
| `fetch_robot.ps1 [-Name rebot_b601_dm]` | 로봇 URDF + 시각 메시 + LICENSE를 고정 커밋에서 받기, SHA256 기록 (`assets/robots/sources.json`) | 최초, 로봇 추가 시 |
| `urdf_mesh_to_usd.ps1 -Urdf <u> -Out <usd>` | 메시(STL) URDF → USD + kinematics.json (.venv-cad) | 로봇 가져오기 |
| `render_robot_pose.ps1 -Usd <usd> [-Pose "j=rad,..."]` | 로봇 USD를 관절 자세 하나로 FK 구동해 렌더 | 로봇 확인 |
| `probe_replicator.ps1` | `omni.replicator.core`를 켜고(처음엔 다운로드) 쓰는 API 시그니처 출력 | Replicator 버전 확인 |
| `generate_dataset.ps1 -Out <dir> -Samples <n> [-Seed]` | 검사 셀 합성 학습 데이터(Replicator, 도메인 랜덤화) → rgb_*.png, labels.csv, dataset.json (`generate_dataset.py`) | 모델 학습 전 |
| `setup_ml_env.ps1` | 학습용 패키지(시스템 Python, `requirements-ml.txt`) 설치 + CUDA 확인 | 최초 1회 |
| `train_inspector_model.ps1 -Dataset <dir> [-Name crown_mil] [-Epochs 20]` | 다시점 MIL CNN 학습 → `config/models/<Name>.onnx/.json`, `results/models/<Name>/` (`train_inspector_model.py`) | 데이터 생성 후 |

`collect_frames.ps1`과 `render_smoke.ps1`은 `-Part kfl08` / `-Part crown`(치아 밀링 라인)으로 제품을 바꾼다(기본 `box`). `render_smoke.ps1`은 검사 셀 레이아웃(크라운)이면 셀 근접 이미지(`_cell.png`)도 저장하고, `_inspection.png`는 스핀들 카메라 화면이다.
| `calibrate_inspector.ps1 -RunDir <보정 run>` | 정상품 프레임으로 기준값 결정 → `config/inspector.json`(box), `inspector_<part>.json`(부품; 검사 셀은 시점별 `{"views": [...]}`) | 조명/색 변경 후 (seed 1 run 사용) |
| `inspect_frames.ps1 [-RunDir] [-Config]` | 저장된 프레임 오프라인 재판정(검사 셀: 시점별 검사기 + 합치기), 지표, 오검출 오버레이 | 수집 후 평가 |

Kit 자동화 스크립트는 `_common.ps1`의 `$KitAutomationArgs`(크래시 창 없음, 저장 확인 없음)를 쓴다. 다른 `kit.exe`가 실행 중이면 경고만 한다.
| `test_core.ps1 [-Filter expr]` | Kit 없는 pytest(`tests/`) | 로직 수정 후 매번 |
| `test_ext.ps1` | Kit 내부 확장 테스트(헤드리스) | Kit 코드 수정 후 |
| `_common.ps1` | 공통 헬퍼(직접 실행 X) | — |

## 처음부터 재현하기
```powershell
.\scripts\setup_kit_template.ps1
.\scripts\build_app.ps1
.\scripts\test_core.ps1
.\scripts\test_ext.ps1
.\scripts\render_smoke.ps1
.\scripts\launch_app.ps1
```
(이 저장소에는 이미 앱과 확장이 포함되어 있으므로 `new_from_template.ps1`은 다시 실행하지 않는다.)
