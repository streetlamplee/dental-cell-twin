# 시뮬레이션 시각과 캡처 추적

- 시뮬레이션 시간은 공정 모델이 진행한 시간, `perf_counter()`는 같은 프로세스에서 실제로 경과한 시간이다. `RTF = sim seconds / wall seconds`로 실행 속도를 기록한다.
- 앱 update 번호, 요청/반환 SWH 프레임 번호, 이미지에서 디코딩한 상태는 별도로 기록한다. 프레임 번호 일치만으로 이미지 내용까지 확인했다고 표현하지 않는다.
- 캡처는 run·generation·request·product·view로 연결한다. 요청, 수신, 검사 완료, 판정 적용, 시간 초과, 취소를 같은 식별자로 추적한다.
- 업데이트 횟수 제한과 실제 경과시간 제한을 별도 종료 사유로 남긴다. Kit 이벤트 루프 자체가 멈추면 외부 프로세스 watchdog으로 감지한다.
- p95 등 정상 수신 지연 통계는 타임아웃 건수와 함께 읽는다. 제외된 실패 요청을 빠뜨린 지연 수치만으로 성능을 판단하지 않는다.
- 요청별 판정 지연과 제품 전체 검사 지연을 구분한다. 다시점 셀의 요청별 지연은 마지막 완료 콜백의 캡처부터 판정까지이며, 전체 시간은 제품의 최초 요청부터 최종 판정까지 trace에서 다시 계산한다. 집계 JSON의 `product_verdict_ms`가 후자다.
- 캡처 지연은 검사 코드에 전달되기까지의 서비스 지연이다. 설치된 Kit 110.4의 `Capture.wait_for_result()`는 기본적으로 완료 후 앱 update를 2회 더 기다린다. 이 대기와 진단용 전달 지연이 포함된 값을 GPU readback 단독 시간으로 해석하지 않는다. 현재 기본 대기는 유지했다.

구현·실험 근거는 [[2026-10-26 면접 준비용 Omniverse 고도화 구현]]에 기록한다. 이미지 내용 검증은 [[셀 카메라에서 프레임 번호가 맞아도 이전 화면이 오는 경우]]와 [[프레임 지정 캡처에서 stale 오탐]]을 구분해서 진행한다.

2026-10-29 box 회귀에서도 요청/반환 프레임 번호가 맞지만 직전 제품과 같은 이미지가 전달된 사례를 확보했다. 제품 20/21은 기대 색상이 다른데 저장 PNG가 같았으며 21번이 오배출됐다. 진단 마커 Stage의 30장 일치 결과를 운영 전체의 내용 정합 보장으로 확대하지 않는다. `scripts/diagnose_capture_duplicates.ps1`로 저장 trace·검사 CSV·이미지를 오프라인에서 연결해 조사할 수 있다. 모든 중복을 stale로 확정하거나 기대 라벨을 런타임 판정에 사용하는 처리는 하지 않는다.

`summary.status=complete`는 실행이 끝나 결과를 저장했다는 뜻이다. 캡처 성공·검사 정확도·회귀 통과를 함께 의미하지 않는다. `check_run`의 타임아웃 감사, 제품별 결과 비교, 실제 이미지 대응을 추가 확인한다. trace CSV를 꺼도 시간 요약은 기록하며 기존 CSV 감사와의 호환성은 `scripts/verify_trace_disabled.ps1`로 확인한다.
