# STP to USD 변환 강화

## 배경
사용자 피드백: "부품이 단순히 네모로 보인다." 원인은 세 가지였다.
1. 변환 옵션이 사용자 `usd_converter`에서 가져온 `tessLOD=0`(extra low)이었다. 곡면이 거친 다각형이 됐다. 크라운은 삼각형 608개, 밀링기 전체는 384개였다.
2. 밀링기 STEP은 URDF의 박스와 원통을 그대로 만든 것이라 모서리가 모두 날카로웠다.
3. GUI를 열면 기본 제품이 박스 라인이었다.

## 결정
| 항목 | 결정 |
|---|---|
| 변환 프로파일 | `config/cad_converter_options.json`를 `profiles`(legacy / machine / product)로 바꾼다. `convert_step_to_usd.ps1 -Profile`로 고른다 |
| 자산 목록 | `config/cad_assets.json`: 자산별 STEP, USD, 프로파일, **LOD와 그 근거**. `convert_all_cad.ps1`이 전부 다시 변환하고 리포트와 URDF 검증까지 한다 |
| LOD 선택 | 측정으로 정한다(`compare_tess_lod.ps1`): 크라운 3, 블랭크 3, 미완성 크라운 3, 밀링기 3, KFL08 2 |
| 품질 검증 | `report_cad_usd.ps1`: USD 메시 부피와 면적을 **STEP B-rep(OpenCascade)의 정확한 값**과 비교, 크기 차이, 메타데이터, 재질 수 |
| 변환 기록 | 변환마다 `<usd>.convert.json`: 변환기 버전, 실제 옵션, 원본 SHA256, 시간, 크기 |
| 사용하는 HOOPS 기능 | `tessLOD`, `accurateSurfaceCurvatures`, `useNormals`, `useMaterials` + `materialType=1`(UsdPreviewSurface), `convertMetadata`(STEP 제품 ID와 이름을 `omni:hoops:metadata:*`로), `sceneOpGenerateUVs`, instancing |
| 밀링기 형상 | `urdf_to_step.py`: 박스 모서리에 필렛(최소 변 × 0.12), 원통 끝에 챔퍼(× 0.1). 평면은 URDF 크기까지 그대로라 bbox는 변하지 않는다(검증 0 mm) |
| GUI 기본 제품 | `part = "crown"`(치아 밀링 라인). 스크립트는 제품을 명시한다(`bench_render`는 box로 고정) |

## 쓰지 않은 것과 이유
- `convertPhysicsData`(B-rep 부피, 무게중심 등): 옵션은 적용됐다는 로그가 나오지만, 이 STEP들에는 속성을 하나도 쓰지 않았다. instancing을 끄거나 `physicsUseGeometryOnRiBRep`을 켜도 같았다. 그래서 B-rep 물리량은 OpenCascade로 직접 계산한다 → [[HOOPS 변환 옵션 실측 (LOD, 문자열 인자, 물리량)]]
- `materialType=2`(OmniPBR): 제품은 변형 레이어가 재질을 다시 바인딩하므로 효과가 없다. 밀링기의 색 검증도 PreviewSurface 기준이라 1로 둔다.
- LOD 4: 크라운 기준 삼각형이 1.8배 늘지만 부피 오차는 0.05 %에서 0.03 %로만 준다.
