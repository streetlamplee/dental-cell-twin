# 실제 CAD 부품을 제품으로 사용

## 요약
컨베이어 제품을 박스에서 **웹에서 구한 실제 부품 STP**로 바꾼다. USD converter로 변환하고, 정상/색상 결함/**부품 누락** 변형을 만들어 검사·분류까지 시뮬레이션한다. 계획서에 새 Day 6으로 추가했다(대시보드 Day 7, 실험 Day 8, 공개 Day 9).

## 배경
- 사용자 요청(2026-10-22): 지금 네모로 처리하는 부품을 실제 CAD STP로 바꿔 Omniverse에서 시뮬레이션하고 싶다.
- 지금은 결함이 파랑 대 빨강 한 종류라 쉬운 문제다(100%가 강건성의 근거가 아님). 계획서 결과물 3번의 "형상/누락" 결함은 아직 없다. 실제 부품을 쓰면 이 둘을 함께 해결할 수 있다.

## 결정
1. **라이선스를 먼저 본다(Gate D).** 이 저장소는 공개 포트폴리오다. 재배포가 허용된 것만 커밋한다(퍼블릭 도메인, CC0/CC-BY/CC-BY-SA, MIT/BSD 등). 출처 URL, 라이선스, 다운로드 날짜, SHA256은 `assets/parts/sources.json`과 `LICENSES.md`에 남긴다.
   - 후보 출처: NIST CAD 모델(퍼블릭 도메인), KiCad 3D 모델 라이브러리(CC-BY-SA), FreeCAD 라이브러리, 라이선스가 명시된 공개 GitHub 저장소
   - 커밋하지 않는 출처: GrabCAD, 3D ContentCentral, 제조사 카탈로그 등 약관이 재배포를 제한하는 곳(필요하면 로컬 전용 + 다운로드 스크립트만 커밋)
   - 대안: CadQuery로 실제 부품을 본떠 직접 모델링
2. **변환은 Day 5와 같은 USD converter 경로를 재사용한다.** 원본 변환 USD는 고치지 않고, 정규화(단위, 원점, 크기, 기본 머티리얼)는 참조 + 오버라이드 레이어로 처리한다.
3. **결함은 원본 형상을 건드리지 않고 만든다.**
   - 색상 결함 = 머티리얼 바인딩만 교체
   - 누락 결함 = 어셈블리 하위 부품 하나를 `active=false`
4. **정답 라벨은 변형 선택에서만 나온다.** 검사기는 계속 픽셀만 받는다. 변형 이름이나 메타데이터를 판정에 쓰지 않는다.
5. **검사기에 형상 검사를 추가한다.** 정상 기준 샘플로 실루엣 면적비, `cv2.matchShapes`, 내부 구멍 수의 허용 범위를 정한다. 판정 이유(color/shape)를 CSV에 기록한다.
6. **박스 제품은 남긴다**(`part=box`). 회귀 비교와 기존 결과 재현에 쓴다.

## 위험
- 위에서 내려다보는 카메라로 누락이 보이지 않을 수 있다 → 부품을 고를 때 "위에서 보이는 특징"을 기준으로 한다. 안 보이면 그 한계를 그대로 기록한다.
- 삼각형 수/VRAM: 30개 제품 × 2 Viewport. 인스턴싱과 `tessLOD`로 관리하고, 파일 크기를 선택 기준에 넣는다.
- STEP 색이 변환 후 사라질 수 있다(`useMaterials=false` 기본) → 정규화 단계에서 기본 머티리얼을 직접 바인딩한다.
- 방향: 우선 고정 방향으로 한다. 무작위 회전은 확장 과제다.
