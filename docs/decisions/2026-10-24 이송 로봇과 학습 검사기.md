# 이송 로봇과 학습 검사기 (Day 12)

사용자 요청: 고도화 1번(reBot Arm 이송)과 2번(합성 데이터 → 모델 → 트윈 안 검증)을 진행한다.

## 1. 이송 로봇: Seeed reBot Arm B601-DM
| 항목 | 결정 |
|---|---|
| 위치 | 셀 앞쪽 `(CELL_X, −0.28)`, 베이스 높이 0.84 m(받침대), +Y(기계 쪽)를 본다 |
| 근거 | 관절 공간 샘플링 결과, 그리퍼가 수직으로 아래를 보는 작업 영역은 베이스 기준 높이 0~0.2 m, 반경 약 0.5 m다. 이 범위에 벨트 끝, 플래터, 다음 벨트가 모두 들어오는 위치를 탐색했다. 모든 경유점이 관절 한계에서 0.29 rad 이상 떨어져 있다 |
| 파지 | 수직 하향, 손가락은 월드 Y로 닫힌다. 집을 때와 놓을 때 공구 자세가 같아서 크라운 방향(yaw)이 유지된다. 검사 시점과 보정값이 이 방향에 의존한다 |
| IK | 6축 감쇠 최소제곱법, 수치 Jacobian, 위치와 자세 오차, 관절 한계 clamp, 시드(이전 경유점 + 결정론적 무작위 40개). 경유점은 **사이클을 만들 때 한 번만** 풀고 허용오차(0.5 mm, 1°)를 검사한다. 시뮬레이션 중에는 IK를 풀지 않는다 |
| 궤적 | 대기 → 집기 위 → 집기(닫기 0.15 s) → 위 → 놓기 위 → 놓기(열기) → 위 → 대기. 관절 공간에서 smoothstep 보간 |
| 시간 | 로딩·언로딩 각 2.0 s(이전 포물선 이송은 0.6 s) → 셀 사이클 5.4 s에서 **8.2 s**, 기본 투입 간격 9 s |
| 자산이 없을 때 | 로봇 USD는 git에 넣지 않는다(메시 21 MB, USD 15 MB). 없으면 같은 시간표로 포물선 이송을 한다. 그래서 run 결과(타이밍, 판정)가 자산 유무와 상관없다 |

## 2. 학습 검사기: Replicator 합성 데이터 → MIL CNN → Kit 안 ONNX
| 항목 | 결정 |
|---|---|
| 데이터 | `generate_dataset.ps1`. 실제 라인 장면을 그대로 쓰고, 셀을 시점 자세로 놓은 뒤 Replicator `BasicWriter`로 스핀들 카메라를 렌더한다 |
| 도메인 랜덤화 | 조명 0.3~1.6배(로그 균등), 키 라이트 방향 ±15°, 셰이드 ±0.03, 제품 방향 0~360°(치핑이 어느 면에든 올 수 있음), 위치 ±1.5 mm, 카메라 ±1/±3 mm |
| 모델 | 다중 인스턴스(MIL) CNN. 시점 5개가 같은 CNN을 거치고, 제품 점수는 시점 점수의 최댓값이다. 치핑은 윗면에서 보이지 않으니 시점별 라벨은 틀린 라벨이 된다. 그래서 제품 라벨 하나로 학습한다 |
| 전처리 | `core/model_inspector.preprocess`(ROI 자르기 → 128×128 → 정규화). 학습과 Kit 추론이 같은 함수를 쓴다. 모델 카드(`config/models/*.json`)가 전처리와 시점, ROI를 기록하고, 맞지 않으면 모델을 쓰지 않는다 |
| Kit 추론 | `onnxruntime-directml`을 처음 쓸 때 `omni.kit.pipapi`로 설치한다(의존 패키지 포함). CPU provider를 쓴다(소형 모델은 CPU가 더 빠름, 실측) |
| 비교 방법 | 같은 run, 같은 프레임에서 규칙 판정과 모델 판정을 **둘 다 기록**한다(`inspections.csv`의 `model_*` 열). 배출에 쓸 판정은 `decision`(기본 rules)으로 고른다 |
| 정직성 | 평가 run(seed 42, 실제 라인)은 학습 데이터에 없다. 학습 검증 세트는 sample id % 5 == 0이다. dark(0.35)는 학습 조명 범위 안이고, bright(2.0)는 범위 밖이다. 이 점을 결과와 함께 밝힌다 |
