# 작업 규칙 - 스크립트화와 Obsidian 문서화

## 요약
빌드/테스트는 모두 `scripts/`의 스크립트로 실행하고, 코드 수정·기획 변경·새로 알게 된 점은 모두 `docs/`에 주제별 Obsidian 노트로 남긴다.

## 배경
7일 계획의 완료 조건은 "신규 환경에서 문서대로 재현 가능"이다. 터미널에 직접 친 명령과 대화 속에만 있는 결정은 재현도 추적도 안 된다.

## 결정
1. **스크립트화:** 빌드/테스트는 `scripts/`에 저장한 스크립트로만 실행한다. 관련 스크립트가 있으면 재사용한다. 인자가 많은 만능 스크립트 대신 목적별로 작은 스크립트를 만든다.
2. **문서화:** `docs/`를 Obsidian vault처럼 쓴다. 노트 하나에는 주제 하나만 담고, `changes / decisions / learnings / topics / progress`로 나눈다.

## 구현
- Claude Code 프로젝트 skill: `.claude/skills/script-workflow/SKILL.md`, `.claude/skills/obsidian-docs/SKILL.md`
- skill은 상황이 맞을 때만 불려오므로, 항상 적용되도록 `CLAUDE.md`에 요약해 연결했다.
