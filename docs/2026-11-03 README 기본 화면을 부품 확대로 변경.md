# 2026-11-03 README 기본 화면을 부품 확대로 변경

## 결정

기존 여섯 구간의 GIF와 각 구간의 설명을 README의 기본 본문에 펼쳐 유지한다. GIF를 960×540으로 확대해 전체 공정과 부품 확대 창을 함께 읽을 수 있게 한다. 투입·로딩·검사·언로딩·배출·티칭의 순서와 각 단계의 구현 설명으로 저장소 전체를 소개한다.

## 적용

- 최종 렌더 `clips_20261102_215142`의 기존 여섯 MP4에서 전체 프레임을 960×540, 10fps GIF로 다시 변환한다.
- `docs/screenshots/clips/01_line.gif`부터 `06_teach.gif`까지 기존 파일 경로와 단계별 구성을 유지한다.
- README에서 여섯 GIF를 원본 960×540 크기의 Markdown 이미지로 표시하고, 각 GIF 바로 아래의 동작·구현 설명을 펼쳐둔다. 별도 HTML 이미지나 접기 태그를 사용하지 않는다.
- 최신 데모 설명 다음에 저장소의 문제 정의·기능·아키텍처·실험·실행 방법을 이어서 읽을 수 있게 한다.
- 과거 정적 이미지 갤러리는 기존 측정 결과 절의 마지막으로 옮기고, 최신 형상 결함 데모와 이전 치핑 실험을 명확히 구분한다.
- `scripts/record_clips.ps1`의 GIF 출력 너비도 960으로 맞춰 다시 녹화할 때 같은 크기를 유지한다.
- 전체 공정 MP4는 로컬 파일임을 표시한다. Git에 포함되는 여섯 GIF로 README의 공정 설명을 직접 볼 수 있다.

## README 재검토

- 중복된 상단 영상 안내를 삭제하고 촬영 정보는 데모 절에 한 번만 설명한다.
- Git에서 제외된 로컬 MP4는 파일 경로로 안내해 저장소에서 열리지 않는 링크를 제거한다.
- 현재 셀 사이클 16.024초, 언로딩 클립 재생 시간 8.2초, 과거 셀 용량 실험의 8.2초 시간표를 구분한다.
- Markdown 파서에서 이미지·링크·절 구조를 확인하고, 여섯 GIF의 실제 크기와 애니메이션 프레임을 검증한다.
- 검증 범위는 파일·Markdown 파서 검사다. 사용자가 보고한 VS Code IDE 미리보기의 깨짐은 실제 화면을 확인하지 못해 미해결 상태이며, 정상 표시가 검증된 것으로 취급하지 않는다.
