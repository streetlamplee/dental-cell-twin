# Day8 대시보드와 이벤트 로그

## 요약
대시보드에서 **제품 라인(box / KFL08 / 치아 크라운 밀링 라인)**, 시드, 제품 수, 불량률, 속도를 고르고, 메인 화면을 **Overview / 밀링기 근접 / 검사 카메라**로 바꿀 수 있다. run마다 `events.csv`를 남기고, 감사 스크립트로 누락을 점검한다. 메인 Viewport 렌더 배율을 낮춰 실행 시간을 줄였다.

## 대시보드 (`dashboard.py`)
| 영역 | 컨트롤 |
|---|---|
| Line setup (Build Scene / Reset 때 적용) | Product 콤보(box, kfl08, crown), Seed, Products, Defect rate |
| 실행 | Build Scene, Start, Stop, Reset, Speed |
| 화면 | View 콤보: Overview / Mill close-up / Inspection camera |
| 상태 | 시간, 투입/검사/벨트 위 제품, 비전 판정 수, 분류 수와 정답 수, late, frame 오류, **밀링기 상태(MACHINING id / idle), 대기열, 가동률** |
| 최근 이벤트 | 최근 5개 |

- 설정은 확장 설정(`/exts/visiontwin.factory/*`)에 쓰고 다음 Build/Reset 때 적용된다. 그래서 run의 설정은 항상 그 run의 `run.json`과 같다.
- `defectRate` 설정이 실제로 컨베이어에 반영되게 했다(이전에는 0.3 고정).

## 이벤트 로그
- `core/event_log.py`: `events.csv` = 시뮬레이션 시간, 제품 ID, 이벤트(SPAWN/LOAD/UNLOAD/INSPECT/VISION/SORT/REJECT/EXIT/STATION), x, 스테이션, 상세(분류 이유, 판정)
- `check_events()`: 제품마다 SPAWN 1, EXIT 1, LOAD = UNLOAD, INSPECT = VISION
- `scripts/check_run.ps1`: events.csv 감사 + summary(미종료, 대기 캡처, 프레임 오류, 타임아웃)

## 렌더 부하
- 메인 Viewport `resolution_scale` = 0.5(설정 `mainViewportScale`). 비전은 검사 Viewport(640×480 고정)만 쓰므로 판정에는 영향이 없다.
- `scripts/bench_render.ps1` (seed 42, box 10개, 앱 시작 포함):

| 배율 | 벽시계 | 시뮬레이션 |
|---|---|---|
| 1.0 | 64.6 s | 23.6 s |
| 0.5 | **53.9 s** | 23.6 s |

  앱 시작(약 20~25 s)을 빼면 약 25~30 % 단축이다. 측정 1회씩이고 PC 사용 상황에 따라 달라질 수 있다.
