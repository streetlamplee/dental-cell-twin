# 데모 자동 녹화

화면 녹화 도구 없이 데모 영상을 스크립트로 만든다: `.\scripts\record_demo.ps1` → `results/demo/dental_cell_twin_demo_<timestamp>.mp4` + `_preview.gif`.

## 동작
- `record_demo.py`는 Kit `--exec` 스크립트로, `run_demo.py`와 같은 흐름을 따른다:
  - 크라운 4개, seed 42, 검사 켬
  - 셀 단계에 따라 화면 자동 전환
  - 라인 종료 후 티칭 펜던트가 원점 + 5면을 재생
- 메인 뷰포트를 `ViewportAPI.resolution = (1280, 720)`으로 고정한다. 2업데이트마다 `capture_viewport_to_buffer`로 캡처해 JPEG로 저장한다.
  - 캡처는 비동기라서 파일 이름은 요청 순번으로 정해 순서를 지킨다.
- 업데이트 1번 = 시뮬레이션 1/60 s(고정 스텝, 동기 렌더)다. 그래서 2업데이트마다 1장을 30 fps로 인코딩하면 **실제 속도**가 된다. 직접 화면 녹화하면 슬로모션이 되던 문제가 없어진다.
- 각 프레임에 cv2로 두 줄을 넣는다:
  - 위: 영어 자막 (단계 설명)
  - 아래: 실제 run 카운터 (sim 시간, 투입·분류·불량 수, 셀 상태)
  - 대시보드 창은 뷰포트 캡처에 안 잡히므로 아래 줄이 대시보드 샷을 대신한다.
- 끝에 결과 이미지 2장을 각 4초씩 붙인다:
  - `readme_views.png`: 치핑은 측면에서만 보임
  - `readme_fig_model.png`: 어두운 조명에서 규칙 FP 29 → 모델 0
- `record_demo.ps1`이 ffmpeg로 인코딩한다:
  - MP4: H.264, crf 20, faststart
  - GIF: 2–16 s 구간, 12 fps, 640 px
  - 다 만들면 프레임 폴더를 지운다.
- `results/demo/`는 git에서 제외했다.

## 첫 녹화에서 고친 점
- **화면 전환 직후 프레임이 회색으로 나옴:** `set_view` 뒤 1업데이트만 기다리고 캡처하면, 전환 직후 한 장이 새 카메라 화면이 아니었다(언로딩 시작 sim 18.1 s). 전환 뒤 4업데이트는 캡처하지 않도록 바꿨다.
- **스핀들 카메라가 기계 몸체만 비추는 구간:** 기계가 첫 시점으로 들어올 때와 마지막 시점 뒤 주차할 때(각 약 0.3–0.4 s), 스핀들 카메라는 기계 몸체만 비춘다. 실제 화면이 맞지만 영상에서는 회색 잡음처럼 보인다. 첫 hold 0.15 s 전부터 마지막 hold 0.15 s 뒤까지만 스핀들 화면을 쓰고, 그 앞뒤는 셀 근접 화면으로 보여 준다("Machine brings / parks the camera").
- **결과 이미지 자막 "29/29"는 과장이었다:** 측정값 그대로 "rule-based 29 false rejects -> learned model 0"으로 고쳤다.
