# GUI 점검과 비전 켜기 버그 수정

녹화 스크립트들은 확장 함수를 직접 부른다(`build_scene_async`, `start`, `set_view`, `open_teach_pendant`). 그래서 **사람이 누르는 대시보드와 티칭 펜던트는 아무도 확인하지 않은 상태였다.** 비전 끔(GUI 기본값)으로 끝까지 돈 run도 0개였다.

## 만든 것: `scripts/gui_check.ps1` + `gui_check.py`
- 앱을 기본 설정(크라운, 비전 꺼짐)으로 연다.
- `omni.kit.ui_test`로 실제 위젯을 마우스로 클릭하고 키보드로 입력한다.
- 단계마다 앱 창 전체를 캡처한다(`omni.kit.renderer_capture.capture_next_frame_swapchain`).
- `results/gui_check/<timestamp>/report.md`에 단계별 PASS/FAIL을 남긴다.

| 단계 | 하는 일 |
|---|---|
| 01 | 기본값 확인 (크라운, Vision 꺼짐) |
| 02 | 제품 수 3 입력, Build Scene |
| 03 | Start, View 콤보로 셀 근접 / 검사 카메라 / 전체 전환 |
| 04 | 비전 끔 run 결과: 3개 모두 통과, `summary.vision = false`, 상태 문구 |
| 05 | Vision 체크 → Reset → Start (Build Scene 없이) |
| 05b | 제품을 바꾸고 Reset → Start |
| 06 | Build Scene → Start (비전 켬): 검사 카메라 창, 판정, 배출 |
| 07 | 티칭 펜던트: 열기, Origin + 5 faces, X 조그, Save point, Play, Export, 닫기 |

## 찾은 문제와 수정
1. **버그: Vision 체크 → Reset → Start 하면 검사 없이 돌고 기록도 남지 않았다.**
   - 상태 "finished (no inspection)", inspectors 0, summary 없음.
   - 원인: 검사 카메라와 검사기는 Build Scene에서만 만든다. 그런데 대시보드에는 "applied on Build Scene / Reset"이라고 적혀 있었다.
   - 수정: `start()`에서 비전이 켜져 있는데 검사 카메라가 없으면, 먼저 만들고(`_enable_vision_then_start`) 시작한다.
   - 분류기(`SortingController(inspection=...)`)도 Reset 때의 비전 값으로 만들어진다. 그래서 run 시작 전(sim time 0)에 다시 만든다.
2. **잠재 버그: 제품을 바꾸고 Reset만 하면, 씬은 그대로인데 카탈로그만 바뀐다.**
   - 원인: `_reset_run_state`가 `_make_catalog`를 다시 부른다.
   - 수정: Build Scene 때의 제품을 `_built_part`로 기억한다. 다르면 Start를 거부하고 "product changed to box: press Build Scene"을 띄운다.
3. **비전 끔 종료 문구가 실패처럼 보였다.**
   - 기본 GUI로 돌리면 끝에 "finished: sorted 1/3 correct"가 떴다. 검사를 안 했으니 불량도 통과하고, 그게 "오분류"로 세어진 것이다.
   - 수정: 비전 끔이면 상태를 "finished: 3 passed (vision off)"로 바꾸고, 카운터에서 correct를 뺐다. `summary.json`의 `sort_correct`는 그대로 기록한다.
4. **테스트 쪽 문제:** `ui_test`의 `input("3")`은 기존 "30" 뒤에 붙여 303이 됐다. `clear_before_input=True`로 바꿨다.

## 결과
- 수정 전: 18단계 중 3개 FAIL
  - 05: 실제 버그
  - 02, 04: 입력 방식 문제와 그 여파
- 수정 후: 모두 PASS. `test_ext`도 통과(5개 테스트)

## 사람이 판단할 것 (자동 점검으로 결정하지 않음)
- 대시보드 창과 검사 카메라 창이 뷰포트 가운데 위에 떠 있어서 장면을 가린다.
  - 오른쪽 패널(Stage/Property)에 도킹할지는 화면 구성의 문제라서 사용자에게 물어본다.
