# Day4 ID 기반 자동 분류

## 요약
배출선에서 **그 제품 객체에 저장된 판정**을 조회해 불량만 배출한다. 판정이 없거나 unknown이면 fail-safe로 배출(격리)하고 이유를 기록한다. 제품별 결과를 `results.csv`와 `summary.json`으로 남긴다.

## 분류 규칙 (`core/sorting.py`)
| 배출선 도달 시 그 제품의 판정 | 경로 | reason |
|---|---|---|
| defect | reject | predicted defect |
| good | pass | predicted good |
| unknown | `unknownPolicy` (기본 reject) | prediction unknown (fail-safe) |
| 아직 없음 | `unknownPolicy` (기본 reject) | no result at reject line (fail-safe) |

- 분류 뒤에 도착한 판정은 `late_prediction`으로 기록만 하고 **적용하지 않는다**.
- 같은 제품이 두 번 분류되면 예외를 던진다.

## 판정과 제품 ID를 묶는 방법
1. 제품이 검사선을 지나는 update에서 그 update 번호로 프레임을 요청한다(프레임 지정 캡처).
2. 콜백에는 요청한 `product_id`가 클로저로 묶여 있다. 판정은 `tracker.get(product_id)` 객체에만 저장된다.
3. 캡처된 프레임 번호가 요청 번호와 다르면(`frame_offset != 0`) 그 판정은 `unknown`으로 처리하고 `frame_mismatches`에 센다.
4. 같은 이미지가 반복되면(stale) 역시 `unknown`.

## 출력
- `results.csv`: 계획서 필수 필드(run_id, seed, product_id, ground_truth, predicted_label, inspection_start_ms, inspection_end_ms, sort_result, simulation_time_s, conveyor_speed, lighting_condition) + score, inspection_latency_ms, sort_reason, sort_correct, late_prediction, final_state
- `summary.json`: sorted, sort_correct, rejected, fail_safe_rejects, late_results, frame_mismatches, stale_frames, frame_target_misses, capture_timeouts, not_exited, pending_frames_at_finalize, simulation_time_s
- `inspections.csv`에 `frame_offset` 컬럼 추가
- 대기 중인 캡처가 모두 끝난 뒤에 쓴다(라인이 먼저 끝나도 마지막 판정이 누락되지 않게).

## 시각화
- 배출선 +Y쪽에 푸셔(노란 막대)를 추가했다. 불량이 배출선에 오면 푸셔가 다가가 제품을 -Y쪽으로 밀고, 제품은 bin으로 떨어지고 푸셔는 돌아온다(0.6초, 시뮬레이션 시간 기준, 시각 전용).

## 설정 (`/exts/visiontwin.factory/...`)
`seed`, `maxProducts`, `speed`, `fixedDt`, `unknownPolicy`, `recordFrames`, `outputDir`, `inspectorConfig`
`collect_frames.ps1`은 `-Seed -Products -Speed`를 받는다.
