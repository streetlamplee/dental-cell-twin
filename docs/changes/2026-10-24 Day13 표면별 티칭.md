# Day13 표면별 티칭

## 요청
사용자는 실제 치아 가공기에서 C축 위 네모난 블록의 윗면과 옆면 4개(총 5면)를 위에서 바라보는 5개 점과, 원점을 합한 6개 점을 티칭해 본 경험이 있다. 마감(2026-10-25 일요일) 때문에 실제 티칭 값은 가져올 수 없다. 그래서 같은 프로그램을 기구학으로 다시 만든다.

## 구현
| 파일 | 내용 |
|---|---|
| `core/teach.py` (새 파일) | `Teacher`: URDF 블록(`c_platter/work`, 35×35×20 mm)의 면 중심과 법선, 공구 끝(`tool_tip`)과 공구 축. `solve_face`: 면이 위를 보는 B/C를 고르고, X·Y·Z를 닫힌 식으로 푼다(B −90° 우선, 플래터가 작업자 쪽인 앞을 봄). `face_program`: 원점 + 5면, 도달 불가 면은 필요한 축값과 함께 거부. `verify`: 각도 오차, 중심 어긋남, 거리, 한계(임의 자세는 가장 가까운 면 기준). `TeachProgram`: 재생(이동 1.0 s, 정지 0.5 s), JSON 저장·불러오기 |
| `teach_pendant.py` (새 파일) | omni.ui 티칭 펜던트: X/Y/Z(mm), B/C(°) 조그 슬라이더, 실시간 검증 표시, "Origin + 5 faces", 점 저장/이동/삭제, 재생, JSON 내보내기 |
| `inspection_cell.py` | `teach_mode()`: URDF 공구와 블록을 보이고 제품 패드를 숨김. `set_joints(q)`: 관절값 직접 지정 |
| `extension.py`, `dashboard.py` | 대시보드 "Teach pendant" 버튼 → 라인 정지, 티칭 모드, 메인 화면을 티칭 근접 카메라로. 펜던트를 닫거나 씬을 다시 만들면 원래 상태로 |
| `scene_manager.py`, `core/layout.py` | 티칭 근접 카메라(`TEACH_CAMERA_*`) |
| `visiontwin.app.kit` | `millUrdf` (블록 형상과 관절) |
| `scripts/render_teach_program.ps1/.py` | 증빙: 6개 점 렌더, 검증표(report.md/json), 프로그램 JSON, 콘택트 시트 |

## 검증 (실측)
- `test_core.ps1` → **98 passed** (티칭 5개: 6개 점 도달과 검증 0, 옆면 B 90°와 C 4방향, 10 mm 미만 옆면 불가, 조그 자세의 면 찾기, JSON과 재생). `test_ext.ps1` → OK
- `render_teach_program.ps1`(거리 20 mm) → `results/teach/<timestamp>/`

| 점 | X | Y | Z (mm) | B | C (°) | 각도 오차 | 중심 어긋남 | 거리 |
|---|---|---|---|---|---|---|---|---|
| origin | 0 | 0 | 0 | 0 | 0 | — | — | — |
| top | −119.95 | 50.98 | −34.1 | 0 | 0 | 0° | 0 mm | 20 mm |
| side_+x / −x / +y / −y | −119.95 | 68.48 | −44.1 | −90 | 90 / 270 / 0 / 180 | 0° | 0 mm | 20 mm |

- **10 mm로 붙이면 옆면 4개는 도달할 수 없다.** Z가 −54.1 mm 필요한데 한계는 −49.1 mm다. 윗면은 가능하다.
- 처음에는 B +90°를 먼저 골랐다. 그러면 크레이들이 앞쪽 카메라에서 블록을 가렸다. 그래서 −90°를 우선으로 바꿨다(둘 다 도달 가능).
- 티칭 모드에서는 스핀들 카메라를 쓰지 않는다. URDF 공구가 카메라 광축 앞 5~30 mm에 있어서 화면을 가린다.

## 한계
- 실제 가공기의 티칭 값과 비교하지 않았다(값을 가져올 수 없음). 기계 치수는 URDF의 임시값이다.
- 충돌 검사가 없다. 점 사이 이동은 관절 공간 보간이다.
